
# Project Safety Rules

## File management
- Never create duplicate files to experiment with a fix.
- Never create names such as file_fixed.py,
  file_v2.py or file_backup.py unless requested.
- Modify the original intended file.
- Preserve existing backups and experimental files.
- Before creating a new file, check whether
  an equivalent file already exists.
- Do not rename or move files without approval.

## Data protection
- Never delete project files without approval.
- Never overwrite raw datasets or original demo files.
- Never modify configuration files unnecessarily.
- Never expose API keys, passwords or secrets.
- Do not commit credentials or environment files.

## Git
- Inspect git status before making changes.
- Never discard uncommitted user changes.
- Never run git reset --hard.
- Never force push.
- Never commit or push without permission.
- Keep changes limited to the requested task.

## Scope control
- Do not refactor unrelated modules.
- Do not redesign existing UI unless requested.
- Do not introduce new dependencies unnecessarily.
- Do not change application behaviour outside
  the requested scope.
