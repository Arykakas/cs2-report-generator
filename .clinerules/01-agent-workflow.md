
# AI Agent Workflow Rules

## Understand before acting
- Always inspect the existing implementation before making changes.
- Understand how relevant files interact with each other.
- Never assume the project architecture.
- Never invent functions, variables, classes, APIs or dependencies.
- Reuse existing components and utilities whenever possible.

## Planning
- For tasks involving multiple files, use Plan mode first.
- Identify the files that need to change.
- Explain the proposed implementation.
- Identify potential risks and dependencies.
- Wait for approval before implementing.

## Implementation
- Make small, focused changes.
- Avoid rewriting entire files when a smaller change is sufficient.
- Preserve existing functionality.
- Follow existing naming conventions and architecture.
- Do not introduce unnecessary abstractions.
- Do not modify unrelated files.

## Tool usage
- Use native file tools for reading, searching and editing files.
- Use terminal tools for execution, testing and Git operations.
- Only use tools and parameters actually available.
- Never invent tool names or capabilities.
- Never execute a command just because it seems plausible.

## Communication
- Explain what you are doing before significant changes.
- Report unexpected errors honestly.
- Never claim a task is complete without verification.
- If uncertain, stop and ask instead of guessing.
